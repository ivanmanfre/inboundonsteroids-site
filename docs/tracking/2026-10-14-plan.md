# Website tracking

Scope accepted by Ivan: both website activity and visitor identification, starting with visits and booking attribution.

1. Record homepage and public case-page visits, booking clicks and case/resource clicks in private Supabase tables. Store path and referrer hostname only. Respect DNT/GPC. Keep owner/test traffic separate.
2. Retain first and latest campaign for 90 days, expire a visit session after 30 minutes idle, and forward all five UTMs to Calendly. Append an opaque session marker to utm_content while retaining its original value in the event data.
3. Add a small fail-soft call after the existing Calendly signature verification. Join trusted created/canceled webhook events to a recorded booking click. Keep canceled bookings out of conversion counts.
4. Test browser attribution/navigation, malformed collector payloads, private access, duplicate events and synthetic webhook booking/cancellation. Review before website release. Verify public files and stored live test events.
5. Company identification: compare free trials; do not commit recurring spend. Account access is separate from first-party tracking.

No n8n changes. Existing lead magnet and content tables stay untouched. Anonymous event collection is observational and can be spoofed; webhook booking confirmation is authenticated. Sources describe campaign attribution, not proof that content caused a booking.
